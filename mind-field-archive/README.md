# MIND FIELD 아카이브: 바이브코딩 워크숍 자료 (v6)

워크숍 자료를 관람 순서 없는 전시장처럼 걷는 사이트입니다.

- 바닥 하나에 조각 63개가 있고, 실 74개가 그 사이를 잇습니다. v6부터 1부는 발표자 민성의 이야기(조각 15개)로 시작합니다.
- v2는 같은 사실을 **정보의 위계와 이미지**로 다시 놓았습니다. 관람자는 카드를 읽기보다 크기와 그림으로 먼저 이해합니다.
- 발표자는 도슨트가 되어 키보드로 조각에서 조각으로 걸어갑니다.

방향과 근거는 [`v2-direction.md`](v2-direction.md)에 있습니다. 어떤 레퍼런스에서 무엇을 가져왔는지, 디자인 시스템 규칙을 어디서 깼는지, 위계를 어떻게 세웠는지를 적었습니다. pass 1은 `../archive-pass1/`에 그대로 있습니다.

## 여는 법

- `index.html`을 브라우저로 바로 엽니다. 빌드 단계와 네트워크 요청이 없습니다. `file://`와 `python3 -m http.server` 두 방식 모두 확인했습니다.
- 특정 조각은 주소 끝에 `#조각id`를 붙여 바로 엽니다(예: `index.html#accounting`). id는 [조각 목록](#조각-목록)에 있습니다.

## v6: 리뷰 반영, 출구, 낱말 풀이

리뷰 다섯 묶음(Muse, Dots, Dots 브라우저 리뷰, 블라인드 리뷰, 페르소나 두 명)을 데스크톱(1440×900, 확인용 1920×1080) 기준으로 반영했습니다. 지시는 "Aesthetics first. Edit archive/ only."였고, 모바일은 이번 범위에서 뺐습니다.

### 새로 생긴 것

- **출구 (5번 구역, `js/exit.js`, `js/exit-data.js`).** 전시의 끝에 "오늘 뭘 만들고 싶은가?"를 묻는 벽이 있고, `5`나 위쪽 메뉴 "출구"로 갑니다.
  - 출발점 다섯 개: 동아리 앱, 포트폴리오 · 의뢰 받기, 반복 업무 자동화, 정보 모으기 도구, 아직 모르겠어요. 하나를 고르면 그 길에 필요한 낱말과 설치 단계만 켜집니다. 길마다 설치기가 묻는 "이번 워크숍에서 무엇을 만들고 싶나요?"(`build/payload/install.sh:324`)의 보기 하나(325행, 예: 개인용 웹앱)가 짝지어져 있어, 설치할 때 무엇을 고를지 알려 줍니다.
  - **바이브코딩 기본 낱말:** 19개를 그림 카드로 보여 줍니다. 낱말 풀이와 같은 데이터(`js/glossary.js`)를 씁니다.
  - **OpenCode 설치:** 원클릭 설치기가 깔아 주는 것 일곱 가지와 설치 여섯 단계, 설치 뒤 할 일을 학생 말로 풀었습니다. 문장마다 `ai-workshop`의 README, `install.sh`, `AGENTS.md`의 줄 번호를 붙였고, `tools/check.py`가 원문과 대조합니다.
  - **AGENTS.md 작업 흐름:** 의도 → 명세 → 지도 → 정밀 작업 → 규율 → 검증의 여섯 단계를 바퀴 그림과 목록으로 보여 줍니다(`AGENTS.md:6-13`).
  - **링크:** 저장소 안 상대 경로(`../build/ssu-opencode-setup.cmd`, `../build/payload/AGENTS.md`, `../build/HANDOFF.md` 등)와 GitHub 주소(`https://github.com/Jeronyhum/ai-workshop/tree/main/build`)를 함께 겁니다. API 키나 토큰은 옮기지 않았습니다. `tools/check.py`가 `js/`, `index.html`, `*.md`에서 키처럼 생긴 문자열을 찾으면 실패합니다.
- **낱말 풀이 (`js/terms.js`, `js/glossary.js`).** 낱말 30개(기본 19개)를 하나의 데이터로 두고, 방, 사례관, 출구, 바닥의 기술 용어에 점선 밑줄을 칩니다.
  - 마우스를 올리거나 키보드로 포커스하면 쉬운 한국어 풀이가 뜹니다. `role="tooltip"`, `aria-describedby`, 최상위 레이어(`popover`)를 쓰고, `Esc`는 풀이만 닫습니다.
  - 바닥의 낱말은 포커스를 받지 않아 도슨트 키(Tab, 방향키)를 막지 않습니다.
  - 위쪽 메뉴의 "용어"나 `T`를 누르면 출구의 낱말 카드가 열립니다.
  - 풀이 중 원문이 있는 것은 출처 줄과 인용을 갖고, `tools/check.py`가 대조합니다. 원문이 없는 풀이는 출처 없이 쉬운 설명만 둡니다.
- **바닥 배경 (`js/field.js`).** 필름 그레인을 걷어 내고, 바닥 아래에 천천히 흐르는 등고선을 WebGL로 그립니다.
  - 구역마다 색이 바뀌고 카메라와 함께 움직입니다.
  - 60% 해상도로 초당 최대 30번 그립니다. 대화상자가 열려 있으면 멈춥니다.
  - 모션 줄임(OS 설정이나 `M`)에서는 시간이 멈추고, 카메라가 움직일 때만 다시 그립니다. WebGL이 없으면 CSS 바닥색만 보입니다.

### 민성의 전사본: 1부 여는 이야기 (추가 지시 t1191u)

민성이 직접 녹음한 나레이션의 블록 C-01–C-20이 이 아카이브의 서사가 되었습니다. 원본은 `materials/transcript/`의 네 파일입니다(근본내용 블록, 사실검증, 메타와 꼬리질문, 빌드브리프). 순위는 이렇습니다.

- 서사와 정의, 비유, 테제는 **블록 파일**이 이전 웹 조사보다 앞섭니다.
- 날짜, 수치, 귀속은 **사실검증 파일**이 블록 파일보다 앞섭니다(빌드브리프 52행).

**바뀐 것:**

- **1부의 시작이 민성의 이야기입니다.** 1부 왼쪽에 폭 3,800의 띠를 새로 깔고, 블록 순서대로 조각 15개를 세웠습니다. 나머지 바닥은 모두 그만큼 오른쪽으로 옮겼습니다(`js/data.js`의 `OPEN`, 한 곳).
  - 1막 역사: 바이브 코딩 2025-02-02, 모델 ≠ ChatGPT, 썰물, 더 크게에서 더 깊게, 딥시크, 두 세대 전 인상.
  - 2막 에이전트의 등장: 도구를 붙이다(Goose, Claude Code), 정의, 하네스, 채팅 ≠ 에이전트, 머리와 손발.
  - 3막 활용: HLE 점수, 가드레일과 환각, 보안, 의도.
  - `1`과 "이야기부터 보기"는 이 띠를 엽니다. 첫 화면에서 밝게 켜지는 조각도 바이브 코딩입니다.
  - 실 18개가 이야기를 블록 순서로 잇고, 이미 바닥에 있던 근거와 만나게 합니다: 회계 100%와 56.4%, GTG 보안 사례, 2부의 하네스 도식과 루프.
- **민성의 말은 그대로 둡니다.** C-09 에이전트 정의, C-10 하네스, C-20 의도 테제를 포함해 그의 문장은 모두 원문 그대로이고, `tools/check.py`가 인용한 바로 그 줄과 대조합니다.
  - 고친 것은 사실검증 (e)표의 음성 인식 오류 하나뿐입니다: "LMM"을 "LLM"으로 읽습니다.

### 성능

헤드리스 Chrome(소프트웨어 GPU)에서 잰 문제와 고친 방법입니다. 실제 GPU에서는 훨씬 빠르지만, 저사양 노트북에서도 같은 방향으로 도움이 됩니다.

- **방이 열릴 때 카메라가 바닥을 미끄러지던 것:** 방 뒤에서 바닥 전체를 매 프레임 다시 그려 한 프레임이 5초까지 걸렸습니다. 이제 방이 열리는 동안 카메라는 멈춰 있고, 바닥이 가려진 뒤에 조각을 맞춥니다. 다 열린 방 뒤의 바닥과 배경은 그리지 않습니다.
- **바닥 전체를 합성 레이어로 올려 두던 것(`will-change: transform`):** 조각 하나가 움직여도 레이어 전체를 다시 그려, 조각 단계에서 초당 1–4프레임이었습니다. 지우고 나서 30프레임입니다. 카메라 전환은 여전히 합성으로 움직이고, 멈추면 글자가 새 배율에서 선명하게 다시 그려집니다.
- **가까이 볼 때 2560px 원본을 풀던 것:** 1280px 중간 사본을 거치게 했습니다(`lod/m/`, 10장).

허락된 라이브러리(three.js, GSAP, Lenis, Motion, OGL, postprocessing, 셰이더)는 **하나도 넣지 않았습니다.** 배경은 직접 쓴 WebGL 셰이더 하나(`js/field.js`, 6.1KB), 낱말 풀이는 브라우저 내장 `popover`(`js/terms.js`, 6.5KB)입니다. 그래서 `vendor/`가 없고 CDN 요청도 없습니다. 이유와 글꼴 라이선스는 [`CREDITS-libs.md`](CREDITS-libs.md)에 있습니다.

### 보는 법

- **바닥:** 작품이 지금 조각이 되면 1단계부터 한 번 스스로 짜이고(단계 사이 1.7초), 끝 프레임에서 멈춥니다. 다른 작품은 끝 프레임으로 쉽니다. 달리는 점과 회전은 화면에 보이고 폭이 220px 이상일 때만 움직입니다(바닥 영상과 같은 규칙).
- **`.` `,`:** 바닥과 방 모두에서 한 단계 앞, 뒤로 갑니다. 바닥에서는 자동 재생을 멈추고 단계를 알림 영역(`aria-live`)에 읽어 줍니다.
- **도슨트 조명(`D`):** 자동 재생 대신 1단계에서 기다립니다. 안내판에 단계 번호, 이름표, 한 줄이 화면 크기로 나오고, 작품의 원문 한 줄이 바닥에 보입니다.
- **방:**
  - 그림은 왼쪽에 붙어 있고, 오른쪽 단계 카드가 화면 가운데를 지날 때마다 그림이 그 단계로 바뀝니다(스크롤 구동, `IntersectionObserver`).
  - 아래의 단계 단추와 `.` `,`도 같은 카드로 스크롤합니다.
  - 좁은 화면에서는 그림이 위에 붙고 카드가 아래로 지나갑니다.
- **글은 이름표뿐입니다.**
  - 원문은 카드마다 "원문"을 펼쳐 보고, 출처 줄이 함께 나옵니다.
  - 방 끝의 "원문과 사실 n"에 기존의 한 줄 요약, 조건, 사실 목록(상태 표시 포함)이 있습니다.
  - 출처와 상태는 방 아래 출처 칸에 그대로 있습니다.
- **모션 줄임:** 단계 전환은 컷이 됩니다. 바닥은 끝 프레임이고, 달리는 점과 회전은 쉬는 자리에 멈춥니다.

### 디자인 에셋 슬롯 (Muse·Dots)

Muse와 Dots의 이미지는 작업 폴더와 Drive 어디에서도 찾지 못했습니다. 그래서 `asset-prompts.md`의 슬롯 8개를 v2 배치에 맞춰 다시 연결하고, 지금은 기존 생성 이미지를 대체로 씁니다.

- **없는 파일을 먼저 요청하지 않는 이유:** 존재 여부를 알려고 없는 파일을 요청하면 브라우저 콘솔에 404 오류가 남습니다. 그래서 `onerror`만으로 감지하지 않고 READY 목록을 둡니다.
- **새로 연결한 자리:**
  - 1부·2부·다리 방의 배경. 오른쪽에서 왼쪽으로 사라지는 마스크를 씌웠고, 지금은 `gen-*` 이미지가 흐리게 보입니다.

  - 종이 재료(`dots-paper-stock`): 대체 없이 단색 bone을 유지합니다.
- **표시:** 바닥 캡션은 그대로 "생성 이미지 · 디자인 에셋"이고, 실제로 쓰인 파일 이름을 보여 줍니다.

## 도슨트 키

| 키 | 하는 일 |
|---|---|
| `←` `→` `↑` `↓` | 그 방향에서 가장 가까운 조각으로 |
| `Tab` | 실로 이어진 다음 이웃으로 걷기. 방금 지나온 조각은 건너뜁니다. 안내판에 다음 이웃이 보입니다 |

| `Enter` | 조각을 방으로 열기 |
| 방 안에서 `←` `→` | 이웃 방으로 걷기, 되돌아가기 |
| `Esc` | 한 단계 물러나기: 방 → 조각 → 구역 → 전체 → 위쪽 도구 |
| `D` | 도슨트 조명: 지금 조각과 이웃, 그 실만 밝게. 실의 이유가 실 위에 뜨고, 안내판이 이웃 목록을 펼치며, 방 글자가 1.2배 커집니다. 2부 도식은 1단계에서 기다리고 안내판에 단계가 나옵니다 |

| `+` `−` | 확대, 축소. 끌어서 걷고, Ctrl과 휠로 확대합니다 |
| `L` | 목록으로 보기 |
| `M` | 모션 기본과 줄임 전환. 처음 값은 운영체제 설정을 따릅니다 |

## 사실 규칙

미감이 다른 모든 규칙보다 앞서지만, 사실은 예외입니다.

- **팩트 게이트는 `package_1105/감독관_감사.md`입니다.** 조각과 줄마다 상태가 붙고, 상태는 모양과 낱말로 표시합니다.
  - ● 확정: 감사 B-1.
  - ◐ 단서: 감사 B-2, 또는 출처가 스스로 밝힌 조건. 조건 문장을 함께 보입니다.
  - ○ 미확인: X 게시물, 이미지, 감사 범위 밖의 카피.
  - ⊘ 제외: 감사 B-3. 취소선으로만 보입니다.
  - / 정정: 감사 B-0. 그은 원문과 고친 말을 나란히 보입니다.
- **쌍으로만 싣는 수치:** "100% vs 37%"는 APEX 56.4%와, GDPval 70.9%는 GDPx 12.0%와, 이론 커버리지 약 90%는 관측 34.3%와 한 그림 안에 놓입니다. 렌더러는 한쪽이 없으면 수치 대신 거절 상자를 그립니다. 증류 조각도 미 당국 권고와 중국 상무부 반박을 함께 실을 때만 렌더합니다.
- **전제 오류 7건(B-0)은 정정으로만 나옵니다:** `h100`, `science`, `papers400`, `poison`, `altman`, `mmlu`, `wwi`.
- **새 그림의 숫자:** 모두 조각의 출처 수치에서 계산했고, 그림마다 환산 방법을 적었습니다.
  - CVE: 연도별 건수 ÷ 100, 반올림. 점 2,711개(`P1_과학난제와지표.md §3.1 :134–141`).
  - 노동시장: 점 100개 중 테두리 90, 채움 34.3(`P1_사무직벤치마크.md §4.1 :176–177`).
  - 한국은행: 28만 5,000 ÷ 1,000 = 점 285개, 그중 26만 8,000 ÷ 1,000 = 268개(`P1_시장산업.md §1-1 :32`).
  - 명명 간격: 글자 크기 ∝ √(일수). 1년 = 365일, 1개월 = 30일, 1주일 = 7일로 환산(`P2_엔지니어링패러다임.md §9 :221`).
- **쓰지 않은 것:**
  - 감사 B-3 전부. 취소선 줄로만 보입니다.
  - 노말틱 영상의 세부 발언. 제목과 링크만 씁니다.
  - H100의 서로 다른 두 지수를 하나의 상승률로 잇는 서술.
  - 클로디아와 Astra 3D 조회수.
  - 학생의미 메타의 다리 B와 F. 감사받지 않은 채용 사례라서 뺐습니다.
- **감사 이후 자료:** `보완_PD수첩_통계검증.md`의 수치(`juniors`, `gap141`)는 감사 뒤의 보완 조사입니다. ◐로 표시하고 "감사 판정 없음"과 "피어리뷰 아님"을 적었습니다.
- **용어 17개(`glossary`):** 감사의 사실 판정 대상이 아닌 풀이라서 ◐로 두었습니다.
- **수치 확인:** `tools/check.py`가 조각에 나오는 숫자를 인용 줄 앞뒤 4줄(차트는 10줄)과 대조합니다.

v6부터 모든 글꼴은 이 사이트가 쓰는 글자만 남긴 WOFF2입니다. 저작권 줄과 라이선스는 `fonts/OFL.txt`와 [`CREDITS-libs.md`](CREDITS-libs.md)에 있습니다. v6 글꼴 정리(민성 t1193u) 뒤로는 세리프, 명조, 궁서, 붓글씨 꼴이 하나도 없습니다.

대체 글꼴 묶음은 한국어가 Pretendard → 나눔고딕 → Apple SD Gothic Neo → 맑은 고딕, 영어가 Inter → Helvetica Neue → Helvetica → Arial입니다. 어느 쪽도 serif로 끝나지 않습니다. 지운 글꼴: Noto Serif KR(명조, 2개 파일 약 420KB), Instrument Serif(세리프, 2개 파일), Gothic A1(쓰이지 않음, 3개 파일).

라틴 글꼴은 `tools/subset_latin.py`로, 한글은 `tools/subset_ko.py`로 다시 만듭니다. 원본 TTF는 `tools/fonts-src/`(Archivo, JetBrains Mono, Inter)와 시스템 글꼴(Pretendard)에 있고 사이트는 내려받지 않습니다.
한글 서브셋은 `tools/subset_ko.py`로 다시 만듭니다. `.ttc`는 `NotoSerifCJK-Bold.ttc#1`처럼 면 번호를 붙입니다.

## 디자인 시스템과 v2

- `css/tokens.css`, `css/base.css`, `css/components.css`는 `site/css/`에서 바꾸지 않고 복사한 그대로입니다.
- v2는 그 위의 `css/archive.css`에서 규칙을 깹니다. 미감이 우선이라는 지시를 따랐습니다. 깬 곳과 이유는 `v2-direction.md`의 "규칙을 깬 곳"에 있습니다:
  - 세리프 글꼴을 더함 (v6에서 걷어 냄: 민성 t1193u)
  - 한 화면에 액센트 둘 이상
  - 바닥 영상 반복
  - 생성 이미지를 더 진하게
  - 쉴 때 실 숨김
  - 상태와 출처를 작게
- 사이트 컴포넌트와 이름이 겹치는 클래스는 아카이브 쪽 이름을 바꿨습니다. v2에서는 `.corr` → `.cx`입니다.

CSS 기법:

| 기법 | 쓰인 곳 |
|---|---|
| `transform` 카메라와 등록된 `@property --z` | 바닥 전체가 한 요소의 `translate() scale()`(v6부터 2D, 합성 레이어로 고정하지 않음). 실 굵기, 라벨, 포커스 테두리는 `calc(… / var(--z))`라서 어느 배율에서도 화면 두께가 같습니다 |
| 컨테이너 쿼리 단위 `cqi` | 작품, 플레이트, 노트, 방의 주인공 그림이 모두 컨테이너입니다. 숫자와 제목 크기가 그 폭을 따르므로, 같은 마크업이 바닥에서는 작품으로, 방에서는 첫 화면으로 커집니다 |
| `:has()` | 조각에 마우스를 올리면 건너는 실이 흐려집니다. 현재 조각이 있을 때만 안내판이 보입니다 |
| `clip-path` | 종이 이면화의 찢긴 아래 가장자리, 방이 조각 자리에서 원으로 열리는 전환 |
| `mix-blend-mode` | 생성 질감(screen) |
| 개별 변형 속성 `translate` | 첫 화면 시퀀스가 카메라 `transform`과 겹치지 않게 조각을 움직입니다 |
| 스크롤 기반 애니메이션 | 방 상단 진행선(`scroll()`), 방의 사실·이웃·연표 줄과 목록 줄의 떠오름(`view()`). `@supports`로 감쌌습니다 |
| SVG 점 시각화 | CVE 점 2,711개, 노동시장 점 100개, 한국은행 점 285개를 데이터에서 계산해 그립니다 |

## 확인한 것

- **`tools/check.py`:** 모두 통과. 조각 48, 실 56, 외부 링크 110개(x-from-drive 30, urls-ok 80).
- **헤드리스 Chrome 1440×900:**
  - 콘솔 오류 0, 가로 넘침 0(`scrollWidth` 1440 = `clientWidth` 1440).
  - 1920×1080과 390×844, 모션 줄임에서도 넘침 0.
- **모든 방:** 48개 방을 차례로 열어 스크립트 오류 0.
  - 이 점검에서, CSS 이름을 바꾸는 치환이 JS의 `p.corr`까지 바꿔 정정 방 6개가 깨진 것을 찾아 고쳤습니다.
- **키보드 스크립트 23개 항목 통과:**
  - 처음부터 `Tab`으로 바닥 도달, 실 따라 걷기, 되돌아가기, 방향키.
  - 방 열기, 이웃 방 오가기, `Esc` 단계.
  - `0` `1` `2` `3`, 도슨트 조명(밝은 조각 수와 밝은 실 수 일치), `L`, `?`, `M`.

  - 250ms: 점만 있는 빈 바닥.
  - 1,100ms: 작품과 플레이트가 올라옴.
  - 2,000ms: 전제 오류의 줄.
  - 3,000ms: 건너는 실.
  - 4,600ms: 정지, 클로디아 영상 재생 중.
- **눈으로 본 화면:**
  - 전체, 각 구역.
  - 도슨트 조명(1920).
  - 방: 회계 이면화, CVE 점의 강, 정정, 패러다임 크기 비교, 노동시장 점 행렬, 그래프 영상.
  - 다리 복도, 휴대폰 폭, 모션 줄임.

## 확인하지 못한 것

- Safari와 Firefox. 스크롤 기반 애니메이션, `@property` 전환, `cqi` 단위는 Chrome 기준이고, 지원하지 않는 브라우저에서는 끝 상태로 보입니다.
- 실제 프로젝터 화면.
- 스크린 리더 실사용. 조각은 `role="button"`과 제목 이름, 바닥 사용법, 현재 조각 알림(`aria-live`)을 갖습니다.
- 바닥 영상 여섯 개가 동시에 도는 상황의 저사양 기기 성능.
- 외부 링크는 목록 파일의 확인 결과를 믿었고 다시 요청하지 않았습니다.
