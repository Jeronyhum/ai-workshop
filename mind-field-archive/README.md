## v4: 2부를 글이 아니라 그림으로

민성의 요청: "디자인 에셋 좀더 받아서 claude한테 좀더 꾸미게 해줘. 특히 2부. 정보를 텍스트가 아닌 이미지로 전달하게 해줘. 인포그래픽과 3blue1brown 같은 스타일로 어려운 내용을 설명하는 식으로 구성하게 해줘."

1단계는 이미지 프롬프트([`asset-prompts-v2.md`](asset-prompts-v2.md))였고, v4는 2단계입니다.

2부의 1순위 작품 다섯 개가 단계 도식이 되었습니다. 도식은 SVG, CSS, JS로만 그렸고 라이브러리는 쓰지 않았습니다. 바탕은 어두운 필드, 선은 계산된 기하입니다. 색은 셋을 씁니다.

- **분필 흰색:** 구조.
- **수학 파랑 `#5CC8E0`:** 흐름과 장(field).
- **산성 초록:** 지금 볼 하나.

선은 스스로 그려지고, 모양은 제 단계에 나타나며, 토큰은 자리를 옮깁니다. `컨텍스트`는 2순위에서 1순위로 올라왔습니다.

- **바닥:** 작품이 지금 조각이 되면 1단계부터 한 번 스스로 짜이고(단계 사이 1.7초), 끝 프레임에서 멈춥니다. 다른 작품은 끝 프레임으로 쉽니다. 달리는 점과 회전은 화면에 보이고 폭이 220px 이상일 때만 움직입니다(바닥 영상과 같은 규칙).

- **도슨트 조명(`D`):** 자동 재생 대신 1단계에서 기다립니다. 안내판에 단계 번호, 이름표, 한 줄이 화면 크기로 나오고, 작품의 원문 한 줄이 바닥에 보입니다.
- **방:**
  - 그림은 왼쪽에 붙어 있고, 오른쪽 단계 카드가 화면 가운데를 지날 때마다 그림이 그 단계로 바뀝니다(스크롤 구동, `IntersectionObserver`).
  - 아래의 단계 단추와 `.` `,`도 같은 카드로 스크롤합니다.
  - 좁은 화면에서는 그림이 위에 붙고 카드가 아래로 지나갑니다.
- **글은 이름표뿐입니다.**
  - 원문은 카드마다 "원문"을 펼쳐 보고, 출처 줄이 함께 나옵니다.
  - 방 끝의 "원문과 사실 n"에 기존의 한 줄 요약, 조건, 사실 목록(상태 표시 포함)이 있습니다.
  - 출처와 상태는 방 아래 출처 칸에 그대로 있습니다.
- **모션 줄임:** 단계 전환은 컷이 됩니다. 바닥은 끝 프레임이고, 달리는 점과 회전은 쉬는 자리에 멈춥니다.

### 디자인 에셋 슬롯 (Muse·Dots)

Muse와 Dots의 이미지는 작업 폴더와 Drive 어디에서도 찾지 못했습니다. 그래서 `asset-prompts.md`의 슬롯 8개를 v2 배치에 맞춰 다시 연결하고, 지금은 기존 생성 이미지를 대체로 씁니다.

- **설정은 `js/assets.js` 한 곳입니다.** 슬롯마다 받을 파일(`assets/dots-*.jpg`, `assets/muse-*.jpg`), 대체(`assets/gen-*.jpg`), 자리를 적었습니다. 재매핑 표는 `asset-prompts.md` 맨 위 "v3: 슬롯 재매핑"에 있습니다.
- **이미지가 도착하면:** `assets/`에 정확한 이름으로 넣고 `python3 tools/assets.py`를 실행하면 그 슬롯이 READY가 되어 새 파일을 씁니다. 새 파일이 깨지면 `onerror`로 대체 이미지로 돌아갑니다.
- **없는 파일을 먼저 요청하지 않는 이유:** 존재 여부를 알려고 없는 파일을 요청하면 브라우저 콘솔에 404 오류가 남습니다. 그래서 `onerror`만으로 감지하지 않고 READY 목록을 둡니다.
- **새로 연결한 자리:**
  - 1부·2부·다리 방의 배경. 오른쪽에서 왼쪽으로 사라지는 마스크를 씌웠고, 지금은 `gen-*` 이미지가 흐리게 보입니다.
  - 목록 보기 배경.
  - 종이 재료(`dots-paper-stock`): 대체 없이 단색 bone을 유지합니다.
- **표시:** 바닥 캡션은 그대로 "생성 이미지 · 디자인 에셋"이고, 실제로 쓰인 파일 이름을 보여 줍니다.

## 바닥 구성

바닥은 10,000 × 5,600 평면입니다.

| 구역 | 1순위 작품 | 바탕 |
|---|---|---|
| **1부 AI 시대의 변화** (0–4,600) | 클로디아 뮤직비디오, AI가 회계사를 이겼다?, 할 수 있다 ≠ 이미 하고 있다, CVE 곡선 | 검은 필드, 흩어진 종이 질감(생성 이미지), dots의 축 이름(가능성, 측정의 함정, 일, 안전, 비용) |
| **다리 학생에게 어떤 의미인가** (4,600–5,600) | 다리 A, C, E (그리고 입구 명판의 사용자 원문) | 엠버 종이 벽(생성 이미지) |
| **2부 에이전트와 만드는 법** (5,600–10,000) | v4: 단계 도식 다섯. 다섯 단계는 대체가 아니라 포괄이다(중심), 무엇을 보여줘야 하는가, 모델 + 하네스 = 에이전트, 당신 자신을 대체하는 시스템, 노드가 일하고 엣지가 넘기고 상태가 흐른다 | 점 격자, 동심원 고리 여섯 개, 휘어진 격자 바탕층과 제목 띠, 왼쪽 끝의 종이에서 격자로 바뀌는 경계(생성 이미지) |

**조각의 세 층**

| 층 | 무엇 | 형식 |
|---|---|---|
| 1순위 작품 | 구역의 논지 | 바닥 폭 860~2,000. 작품마다 형식이 다릅니다: 영상, 종이 이면화, 점 행렬, 점의 강, 크기 비교, 등식, 원형 도식, 세리프 문장 |
| 2순위 플레이트 | 강한 숫자 하나나 이미지 하나 | 폭 420~640. 위에 숫자나 이미지, 아래에 세리프 제목과 한 줄 |
| 3순위 노트 | 전제 오류, 보조 사실, 빈자리 | 상자 없는 문장 조각. 정정은 빨간 줄로 그은 원문과 고친 말 |

**세 장면**

- 전체(`0`): 작품과 고리와 복도만 눈에 들어옵니다. 지도와 확대 버튼은 숨겨집니다.
- 구역(`1`, `2`, `3`): 플레이트가 읽힙니다.
- 조각 확대: 노트와 출처까지 읽힙니다.

## 도슨트 키

| 키 | 하는 일 |
|---|---|
| `←` `→` `↑` `↓` | 그 방향에서 가장 가까운 조각으로 |
| `Tab` | 실로 이어진 다음 이웃으로 걷기. 방금 지나온 조각은 건너뜁니다. 안내판에 다음 이웃이 보입니다 |
| `Shift` `Tab` | 걸어온 길을 한 걸음 되돌아가기 |
| `Enter` | 조각을 방으로 열기 |
| 방 안에서 `←` `→` | 이웃 방으로 걷기, 되돌아가기 |
| `Esc` | 한 단계 물러나기: 방 → 조각 → 구역 → 전체 → 위쪽 도구 |
| `D` | 도슨트 조명: 지금 조각과 이웃, 그 실만 밝게. 실의 이유가 실 위에 뜨고, 안내판이 이웃 목록을 펼치며, 방 글자가 1.2배 커집니다. 2부 도식은 1단계에서 기다리고 안내판에 단계가 나옵니다 |
| `.` `,` | 2부 도식을 한 단계 앞, 뒤로. 바닥과 방 모두 |
| `0` `1` `3` `2` | 전체, 1부, 다리, 2부 |
| `+` `−` | 확대, 축소. 끌어서 걷고, Ctrl과 휠로 확대합니다 |
| `L` | 목록으로 보기 |
| `M` | 모션 기본과 줄임 전환. 처음 값은 운영체제 설정을 따릅니다 |
| `?` | 키 지도 |

- 글자 키는 `KeyboardEvent.code`를 쓰고 IME 조합 중인 입력은 무시합니다. 한글 입력 상태에서도 작동합니다.
- 바닥 위에서는 `Tab`이 실을 따라 걷는 데 쓰입니다. 바닥을 벗어나려면 `Esc`로 위쪽 도구까지 나갑니다.

## 사실 규칙

  - ● 확정: 감사 B-1.
  - ◐ 단서: 감사 B-2, 또는 출처가 스스로 밝힌 조건. 조건 문장을 함께 보입니다.

  - ⊘ 제외: 감사 B-3. 취소선으로만 보입니다.

## 디자인 시스템과 v2

- `css/tokens.css`, `css/base.css`, `css/components.css`는 `site/css/`에서 바꾸지 않고 복사한 그대로입니다.
- v2는 그 위의 `css/archive.css`에서 규칙을 깹니다. 미감이 우선이라는 지시를 따랐습니다. 깬 곳과 이유는 `v2-direction.md`의 "규칙을 깬 곳"에 있습니다:
  - 세리프 글꼴을 더함
  - 한 화면에 액센트 둘 이상
  - 바닥 영상 반복
  - 생성 이미지를 더 진하게
  - 쉴 때 실 숨김
  - 상태와 출처를 작게
- 사이트 컴포넌트와 이름이 겹치는 클래스는 아카이브 쪽 이름을 바꿨습니다. v2에서는 `.corr` → `.cx`입니다.

CSS 기법:

| 기법 | 쓰인 곳 |
|---|---|
| `transform` 카메라와 등록된 `@property --z` | 바닥 전체가 한 요소의 `translate3d() scale()`. 실 굵기, 라벨, 포커스 테두리는 `calc(… / var(--z))`라서 어느 배율에서도 화면 두께가 같습니다 |
| 컨테이너 쿼리 단위 `cqi` | 작품, 플레이트, 노트, 방의 주인공 그림이 모두 컨테이너입니다. 숫자와 제목 크기가 그 폭을 따르므로, 같은 마크업이 바닥에서는 작품으로, 방에서는 첫 화면으로 커집니다 |
| `:has()` | 조각에 마우스를 올리면 건너는 실이 흐려집니다. 현재 조각이 있을 때만 안내판이 보입니다 |
| `clip-path` | 종이 이면화의 찢긴 아래 가장자리, 방이 조각 자리에서 원으로 열리는 전환 |
| `mix-blend-mode` | 생성 질감(screen) |
| 개별 변형 속성 `translate` | 첫 화면 시퀀스가 카메라 `transform`과 겹치지 않게 조각을 움직입니다 |
| 스크롤 기반 애니메이션 | 방 상단 진행선(`scroll()`), 방의 사실·이웃·연표 줄과 목록 줄의 떠오름(`view()`). `@supports`로 감쌌습니다 |
| SVG 점 시각화 | CVE 점 2,711개, 노동시장 점 100개, 한국은행 점 285개를 데이터에서 계산해 그립니다 |

## 확인한 것

- **`tools/check.py`:** 모두 통과. 조각 48, 실 56, 외부 링크 110개(x-from-drive 30, urls-ok 80).
- **헤드리스 Chrome 1440×900:**
  - 콘솔 오류 0, 가로 넘침 0(`scrollWidth` 1440 = `clientWidth` 1440).
  - 1920×1080과 390×844, 모션 줄임에서도 넘침 0.
- **모든 방:** 48개 방을 차례로 열어 스크립트 오류 0.
  - 이 점검에서, CSS 이름을 바꾸는 치환이 JS의 `p.corr`까지 바꿔 정정 방 6개가 깨진 것을 찾아 고쳤습니다.
- **키보드 스크립트 23개 항목 통과:**
  - 처음부터 `Tab`으로 바닥 도달, 실 따라 걷기, 되돌아가기, 방향키.
  - 방 열기, 이웃 방 오가기, `Esc` 단계.
  - `0` `1` `2` `3`, 도슨트 조명(밝은 조각 수와 밝은 실 수 일치), `L`, `?`, `M`.
- **첫 화면 시퀀스:** 250, 1,100, 2,000, 3,000, 4,600ms에서 프레임을 찍어 단계를 확인했습니다.
  - 250ms: 점만 있는 빈 바닥.
  - 1,100ms: 작품과 플레이트가 올라옴.
  - 2,000ms: 전제 오류의 줄.
  - 3,000ms: 건너는 실.
  - 4,600ms: 정지, 클로디아 영상 재생 중.
- **눈으로 본 화면:**
  - 전체, 각 구역.
  - 도슨트 조명(1920).
  - 방: 회계 이면화, CVE 점의 강, 정정, 패러다임 크기 비교, 노동시장 점 행렬, 그래프 영상.
  - 다리 복도, 휴대폰 폭, 모션 줄임.

## 확인하지 못한 것

- Safari와 Firefox. 스크롤 기반 애니메이션, `@property` 전환, `cqi` 단위는 Chrome 기준이고, 지원하지 않는 브라우저에서는 끝 상태로 보입니다.
- 실제 프로젝터 화면.
- 스크린 리더 실사용. 조각은 `role="button"`과 제목 이름, 바닥 사용법, 현재 조각 알림(`aria-live`)을 갖습니다.
- 바닥 영상 여섯 개가 동시에 도는 상황의 저사양 기기 성능.
- 외부 링크는 목록 파일의 확인 결과를 믿었고 다시 요청하지 않았습니다.
