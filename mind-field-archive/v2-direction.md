# v2 방향: 정보의 나열에서 위계와 이미지로

사용자 요청(원문): "디자인을 정보의 나열로 표현하지 말고, 정보의 위계와 이미지로 관람자가 이해하고, 생각하게 구성해줘. 구글 드라이브의 레퍼런스와 UI, 모션 그래픽 등을 더 참고하게 하고, 최대한 OPUS 5.5에게 모든 제약 사항보다 미감 그 자체를 더 중시하라고 전달해줘"

## 우선순위

1. **미감이 먼저입니다.** MIND FIELD 규칙(팔레트, 프레임당 액센트 1색, 재료, 토큰, 밀도)보다 앞섭니다. 더 아름다우면 규칙을 깹니다.
2. **예외는 하나, 사실입니다.** 사실, 숫자, 이름, 날짜, URL은 refs에서만 가져옵니다. 조각마다 출처와 상태를 남기되 조용하게 둡니다. 시각화도 이 규칙을 따릅니다. 점 하나가 몇 건인지 적고, 반올림했다고 적습니다.

## pass 1의 문제

pass 1은 조각 48개를 거의 같은 크기의 카드로 바닥에 깔고, 실 56개를 모두 같은 굵기로 그렸습니다.

- 전체를 보면 빨간 실이 엉킨 증거판입니다. 눈이 갈 곳이 없습니다.
- 조각 하나하나는 제목, 요약, 상태, 출처가 같은 비중으로 쌓인 카드입니다. 관람자가 그림을 보지 않고 글을 읽게 됩니다.
- 이미지는 카드 안의 썸네일이었고, 숫자는 카드 크기에 갇혀 있었습니다.

사용자가 말한 "정보의 나열"이 바로 이것입니다.

## 규칙을 깬 곳 (미감 우선)

- **글꼴을 더합니다.**
  - 문장은 세리프: 한국어 Noto Serif KR Bold, 라틴 Instrument Serif. 모두 OFL.
  - 숫자는 Archivo 압축체 그대로 둡니다.
  - 근거: motion_so, okapi, tobiadonadon 모두 크고 짧은 세리프 문장이 화면을 끕니다. `디자인레퍼런스.md` §5도 "거대 세리프 또는 타이트한 그로테스크"라고 적었습니다.
- **액센트를 한 화면에 둘 이상 씁니다.** 1부와 2부를 잇는 실은 엠버로 남기고, 다리 문장은 엠버와 bone, 2부 고리 위의 이미지는 제 색을 그대로 씁니다.
- **영상이 바닥에서 소리 없이 돕니다.** pass 1은 "정보에 무한 반복 금지"를 따랐습니다. 이 영상들은 정보가 아니라 이미지이므로 화면 안에 들어왔을 때만 재생합니다. 모션 줄임에서는 포스터만 보입니다.
- **생성 이미지를 더 진하게 씁니다.** 다리 복도의 종이 이미지는 벽 그 자체가 되고, 1부 질감도 더 잘 보입니다. 표시는 그대로 "생성 이미지 · 디자인 에셋"입니다.
- **실을 숨깁니다.** 쉴 때는 1부와 2부를 건너는 실만 희미하게 보입니다. 나머지 실은 조각에 다가가거나(호버, 포커스) 도슨트 조명을 켜면 그 조각의 실만 그려집니다.
- **상태와 출처를 작게 둡니다.** 조각에는 모양 기호, 낱말, 파일 이름만 낮은 대비로 남깁니다. 전체 출처는 방의 맨 아래에 있습니다. 상태를 색만으로 구별하지 않는다는 규칙은 지킵니다(모양과 낱말).

## 새 위계

**세 층.** 크기가 위계입니다. 겉모양이 같은 카드는 없습니다.

| 층 | 무엇 | 바닥에서의 크기 | 형식 |
|---|---|---|---|
| 1순위 작품 | 구역마다 4점. 그 구역의 논지를 하나의 그림으로 | 폭 1,700~2,200 | 거대한 숫자, 점 시각화, 큰 영상, 거대한 세리프 문장. 작품마다 형식이 다릅니다 |
| 2순위 플레이트 | 강한 숫자 하나나 이미지 하나가 있는 근거 | 폭 480~760 | 위에 숫자나 이미지, 아래에 세리프 제목, 한 줄 |
| 3순위 노트 | 전제 오류, 보조 사실, 빈자리 | 글자 조각만 | 상자 없음. 정정은 그어진 원문과 고친 말 |

**1순위 작품.**

| 구역 | 작품 | 그림 |
|---|---|---|
| 1부 가능성 | 클로디아 뮤직비디오 | 영상이 큰 화면으로 돕니다 |
| 1부 측정의 함정 | AI가 회계사를 이겼다? | 100%와 56.4%가 종이 위에서 마주 선 이면화. 한쪽만으로는 그려지지 않습니다 |
| 1부 일 | 할 수 있다 ≠ 이미 하고 있다 | 점 100개: 테두리 점 약 90개(이론), 채운 점 34.3개(관측) |
| 1부 안전 | CVE 곡선 | 72,812와 점의 강. 2019~2026 Q1–Q3, 점 하나 = 100건, 반올림 |
| 다리 | 사용자 원문 명판, 다리 A, C, E | 복도 벽에 큰 세리프 문장 셋 |
| 2부 중심 | 다섯 단계는 대체가 아니라 포괄이다 | 명명 간격 "약 3년, 약 3개월, 약 2개월, 약 1주일, 1개월 간격"을 글자 크기로. 크기는 간격의 제곱근에 비례하고, 그렇게 적어 둡니다 |
| 2부 하네스 | Agent = Model + Harness | 거대한 등식 |
| 2부 루프 | 당신 자신을 대체하는 시스템 | Goal → Action → Observation → Adjustment를 원으로 |
| 2부 그래프 | 노드가 일하고, 엣지가 넘기고, 상태가 흐른다 | 서브에이전트 스웜 영상이 큰 화면으로 |

**2순위와 3순위.** 1순위는 모두 11점입니다(1부 4, 다리 3, 2부 4). 2순위 25점은 1순위 작품 사이의 길목에 놓입니다. 3순위 12점은 작품 주변에 흩어진 문장 조각입니다. 순서는 정하지 않습니다. 실은 그대로 56개입니다.

**방(상세 보기).** 시안 PNG의 순서를 따릅니다.
1. 주인공 그림이 첫 화면을 채웁니다.
2. 세리프 제목과 한 줄(출처의 문장)이 겹쳐 놓입니다.
3. 조건 한 줄이 따라옵니다.
4. 분해된 사실이 작게 놓입니다.
5. 이미지 띠가 이어집니다.
6. 출처와 링크는 맨 아래 작은 글씨입니다.
7. 이웃 방은 그림이 있는 띠로 이어집니다.

## 모션

| 언제 | 기법 | 값 |
|---|---|---|
| 첫 화면, 한 번 | spark → build → twist → lock → hold | spark 0–480ms(빨간 점, 0.3 → 1.2 → 1), build 480–1,700ms(구역 제목과 1순위 작품이 흐림 속에서 올라옴, 간격 70ms), twist 1,700–2,700ms(전제 오류에 줄이 그어지고 고친 말이 나타남), lock 2,700–3,500ms(건너는 실이 그려지고 카메라가 1.03배에서 제자리로), 그 뒤 hold |
| 조각에 다가갈 때 | easing → overshoot → stagger → holds | 조각이 `cubic-bezier(0.34, 1.45, 0.64, 1)`로 1.02배까지 넘쳤다 자리 잡고, 그 실이 40ms 간격으로 그려진 뒤 멈춥니다 |
| 방을 열 때 | 숫자 굴림 | 자리마다 8px 아래, 블러 2px에서 500ms, 간격 70ms |
| 방을 닫을 때 | 빠른 퇴장 | 200ms |
| 모션 줄임 | 끝 상태 | 모든 시퀀스가 마지막 프레임으로 바로 갑니다. 영상은 포스터만 보입니다 |
