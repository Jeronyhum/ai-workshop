# 기능 명세: SSU x OpenCode 원클릭 설치기

**기능 브랜치**: `001-oneclick-installer`
**작성일**: 2026-11-04
**상태**: 구현 완료 (재검증 반영본)
**입력**: HANDOFF.md §2 사용자 프롬프트 원문 (2026-11-04 수거본)

## 사용자 시나리오 및 테스트

### 사용자 스토리 1 — 클릭 한 번으로 전부 설치 (우선순위 P1)

바이브코딩 워크숍 참가자(생초짜, 개발 도구 미설치 상태)가 설치 파일 하나를 받아
실행하면, 자기 OS에 맞는 OpenCode **Desktop 앱**과 기반 프로그램(Node.js, Git,
uv)이 자동으로 설치되고, API 키 입력 한 번으로 SSU BAZE 게이트웨이의 모델과
도구를 OpenCode에서 바로 쓸 수 있다.

**왜 이 우선순위인가**: 워크숍의 전제 조건이다. 여기서 막히면 참가자는 수업에
참여 자체를 못 한다.

**독립 테스트**: 빈 OS 사용자 계정에서 설치 파일을 실행하고, OpenCode를 열어
모델 목록에 BAZE 모델이 보이고, 그 모델로 첫 메시지를 보내 답이 오는지 확인한다.

**수락 시나리오**:

1. **주어진 조건** 아무것도 설치되지 않은 Windows/macOS/Linux,
   **행동** 설치 파일을 실행하고 발급받은 API 키를 입력하면,
   **결과** Desktop 앱·CLI·기반 프로그램이 설치되고 키가 검증된다.
2. **주어진 조건** 설치 완료 직후, **행동** OpenCode Desktop을 열면,
   **결과** 모델 선택 목록에 게이트웨이 채팅 모델 61개(Claude/GPT/호환 레인)가 보인다.
3. **주어진 조건** 위 상태, **행동** BAZE 모델로 메시지를 보내면,
   **결과** 게이트웨이로 인증 헤더와 함께 요청이 나가고 응답이 돌아온다.

### 사용자 스토리 2 — 첫 랜딩에서 의도부터 묻는다 (우선순위 P1)

설치 후 첫 세션에서 OpenCode가 곧바로 코드를 쓰지 않고, 참가자가 만들고 싶은
제품을 먼저 묻는다. 코치 스킬(vibe-coach)이 의도, 유사 제품, 예상 API와 비용,
스택을 단계별로 끌어내고 합의를 만든 뒤에 구현을 시작한다.

**독립 테스트**: 새 세션을 열고 아무 말이나 입력했을 때 코치가 질문부터 하는지,
그리고 설치 시 입력한 의도(PROJECT_INTENT.md)가 첫 대화에 반영되는지 확인한다.

**수락 시나리오**:

1. **주어진 조건** 설치 시 의도(분류+한 문장)를 입력한 상태,
   **행동** 첫 세션을 시작하면,
   **결과** 그 의도를 읽은 코치가 확인 질문 3개 이하로 시작한다.
2. **주어진 조건** 의도를 "(아직 구체화되지 않음)"으로 비운 상태,
   **행동** 설치 완료 안내를 보면,
   **결과** 시딩 문구가 플레이스홀더가 아니라 선택한 분류 라벨로 표시된다.

### 사용자 스토리 3 — 크레딧과 컨텍스트가 항상 보인다 (우선순위 P2)

참가자는 남은 크레딧(잔액/할당, %)과 현재 세션의 컨텍스트 사용량을 화면 우측
상단 원형 그래프(HUD)에서 본다. 500k 컨텍스트 창을 전제로, 압축이 필요해지기
전에 스스로 인지할 수 있어야 한다.

**독립 테스트**: 세션을 진행하며 HUD 수치가 실제 사용량과 함께 움직이는지,
크레딧 조회가 실패해도 컨텍스트 표시는 살아 있는지 확인한다.

**수락 시나리오**:

1. **주어진 조건** HUD 실행 중, **행동** 모델을 호출하면,
   **결과** 크레딧 잔액과 컨텍스트 %가 갱신된다.
2. **주어진 조건** 세션 DB를 읽을 수 없는 상태, **행동** HUD가 상태를 조회하면,
   **결과** 크레딧 정보는 그대로 표시되고 컨텍스트만 오류로 표시된다(전체 소멸 금지).

### 사용자 스토리 4 — 코드 탐색 레이어와 워크플로 (우선순위 P2)

Serena(심볼 단위 코드 탐색·편집)가 MCP 서버로 등록되고 graphify(프로젝트 구조
지도)가 스킬로 등록돼, AGENTS.md의 단일 워크플로(의도 → 명세 → 지도 → 정밀
작업 → 규율 → 검증) 안에서 함께 동작한다. pstack 스킬 58개와 spec-kit
(`/speckit.*`)이 설치돼 엄격한 엔지니어링 워크플로를 그대로 쓸 수 있다.
(Headroom은 2026-11-04 소유자 결정으로 제외됐다: MCP 등록만으로는 자동
압축이 일어나지 않고 설치가 수 GB로 무거웠다.) 게이트웨이의 비채팅 기능(이미지·영상·오디오·
임베딩·리랭크·의사결정·실시간)은 채팅 모델로 등록할 수 없으므로, 개발자 문서
기준으로 MCP 도구(ssu-bridge: Exa 검색, decide, usage, credits)와 게이트웨이
MCP 스위트로 연결한다.

**독립 테스트**: 설치 후 `opencode mcp list`와 스킬 목록에서 serena,
ssu-bridge, pstack 스킬이 확인되고 `/credits`가 실제 잔액을 답하는지 확인한다.

**수락 시나리오**:

1. **주어진 조건** 설치 완료, **행동** `/credits`를 실행하면,
   **결과** 지어낸 숫자가 아닌 게이트웨이 실측 잔액이 보고된다.
2. **주어진 조건** 설치 완료, **행동** Exa 깊은 검색을 호출하면,
   **결과** 5초를 넘겨도 타임아웃으로 끊기지 않고 결과가 돌아온다
   (게이트웨이가 과금한 뒤 클라이언트가 끊는 상황 금지).

### 엣지 케이스

- 키가 틀렸거나 게이트웨이가 거부하면, 같은 키를 반복 검증하지 말고 새 키를
  다시 입력받는다. 최종 실패 시에도 계속 진행할지 사용자가 선택한다.
- 설치 중간 단계(설정 재생성, 스킬 정규화)가 실패하면, 실패를 숨기지 않고
  어느 단계가 왜 실패했는지 알려준다. 성공하지 않은 것을 [OK]로 표시하지 않는다.
- 연습 모드(SSU_DRY_RUN=1)는 실제로 아무것도 설치하거나 쓰지 않으며, 끝까지
  정상 종료(exit 0)한다.
- 기존 설정(opencode.json, AGENTS.md)이 있으면 백업 후 교체한다.
- Linux에서 데스크톱 패키지 설치에 관리자 권한이 없으면 AppImage로 대체한다.

## 요구사항

### 기능 요구사항

- **FR-001**: 설치기는 단일 파일(.cmd 폴리글롯)이어야 하며 Windows에서는
  더블클릭, macOS/Linux에서는 bash 실행으로 동일하게 동작해야 한다.
- **FR-002**: 설치기는 OS별로 OpenCode Desktop 앱과 CLI, Node.js 22.5+,
  Git, uv를 자동 설치해야 한다. Linux도 Desktop 앱이 설치 대상이다(CLI만으로
  대체 금지).
- **FR-003**: API 키는 화면 입력(숨김) 또는 환경변수로만 받는다. 키를 로그나
  안내 문구에 평문으로 출력하지 않는다.
- **FR-004**: 생성되는 `opencode.jsonc`는 설치 대상 OpenCode 버전이 실제로
  로드하는 스키마여야 한다. 검증 기준은 "파일에 적힌 개수"가 아니라
  `opencode debug config`에 provider가 npm·options와 함께 남고
  `opencode models`에 모델이 나열되는 것이다.
- **FR-005**: 게이트웨이 카탈로그의 채팅 모델 전수(기준 시점 61개)를 사고 수준
  프로필(variants)과 함께 등록한다. variants는 OpenCode가 요구하는 객체 맵
  형태여야 하며, 모델 항목의 비용·모달리티·추론 필드는 로더가 유지하는
  키(cache_read/cache_write, modalities, reasoning)만 사용한다.
- **FR-006**: 인증은 OpenCode 실행 환경에서 실제로 해석돼야 한다. 설정 폴더의
  .env는 `{env:...}` 치환으로 해석되지 않음이 실측됐으므로, 생성 설정에 키를
  직접 넣고 파일 권한을 소유자 전용(0600)으로 한다. .env는 bridge/HUD가
  스스로 읽기 때문에 함께 유지한다.
- **FR-007**: 게이트웨이 MCP 스위트, ssu-bridge, Serena를 flat한
  `mcp` 맵으로 등록하고, 오래 걸리는 도구(Exa 등)에는 기본 5초를 넘는
  타임아웃을 명시한다. graphify는 MCP가 아니라 스킬+CLI로 등록한다
  (`graphify install --platform opencode`).
- **FR-013**: 설치되는 AGENTS.md는 코치·spec-kit·graphify·Serena·pstack을
  하나의 워크플로(의도 → 명세 → 지도 → 정밀 작업 → 규율 → 검증)로
  라우팅해야 한다.
- **FR-014**: HUD 상태에는 누적 토큰 사용량과 프롬프트 캐시 적중률
  (cache.read / (input + cache.read))이 포함돼야 한다.
- **FR-015**: OpenCode(데스크톱·CLI)가 이미 설치돼 있으면 해당 설치를
  건너뛰고, 키 입력 단계에서는 게이트웨이 대시보드를 브라우저로 열어준다.
- **FR-008**: 컨텍스트 상한은 500k로 캡한다. HUD는 크레딧과 컨텍스트를 각각
  독립적으로 조회해 한쪽 실패가 다른 쪽을 지우지 않는다.
- **FR-009**: pstack 스킬은 name+description만 남기는 정규화를 거쳐 설치하되,
  OpenCode 이름 규칙을 어기는 스킬은 조용히 누락하지 말고 skip 사유와 함께
  보고한다. 부분 설치는 종료 코드로 구분 가능해야 한다.
- **FR-010**: 설치기는 단계별 실패를 삼키지 않는다. 복사 실패, 설정 재생성
  실패는 즉시 중단하거나 명시적으로 경고한다.
- **FR-011**: 빌드는 어느 OS에서든 가능해야 한다(build.mjs). 빌드 산출물의
  인코딩 규칙: .ps1은 UTF-8 BOM 부착, install.sh는 BOM 금지(셰뱅 파손),
  전체 CRLF.
- **FR-012**: 설치 폴더의 명령·스킬은 OpenCode 문서상의 복수형 경로
  (commands/, skills/)에 배치한다.

### 핵심 엔터티

- **설치 파일**: 폴리글롯 .cmd. 배치 헤더, base64 ZIP 페이로드, 유닉스
  부트스트랩으로 구성.
- **생성 설정(opencode.jsonc)**: 게이트웨이 카탈로그에서 라이브 생성되는
  provider/MCP 정의. 키를 포함하므로 소유자 전용 파일.
- **의도 파일(PROJECT_INTENT.md)**: 참가자가 설치 때 남긴 분류와 한 문장.
  첫 세션의 코치 동작을 결정한다.

## 성공 기준

### 측정 가능한 결과

- **SC-001**: 빈 계정 실측에서 설치 완료 후 `opencode models`에 카탈로그의
  채팅 모델 전수가 나열된다 (기준 시점 61개, 카탈로그 변동 시 그 전수).
- **SC-002**: BAZE 모델로의 테스트 호출에서 게이트웨이가 받는 요청에 유효한
  Authorization 헤더가 포함된다 (헤더 없음 = 실패).
- **SC-003**: 드라이런이 세 OS 경로 모두에서 실제 변경 없이 exit 0으로 끝난다.
- **SC-004**: `/credits` 응답 숫자가 게이트웨이 credits 엔드포인트 응답과
  일치한다 (지어낸 수치 0건).
- **SC-005**: 부분 실패 시뮬레이션(스킬 1개 이름 규칙 위반 주입)에서 설치기가
  해당 스킬의 skip을 이름과 사유로 보고한다.

## 가정

- 참가자의 키는 숭실대 제공 BAZE(factchat) 게이트웨이 키이며, 카탈로그는
  설치 시점에 라이브 조회한다.
- 모델 직접 호출 검증은 키 소유자(주최 측)가 별도로 수행한다. 설치기 자체의
  정적 검증 범위는 FR-004의 로더 실측까지로 한다.
- OpenCode 기준 버전은 1.19.x다. 스키마 실측 결과는 버전에 종속되므로,
  OpenCode 메이저 업데이트 시 FR-004 검증을 다시 수행한다.
